# Технічне завдання: форма №9

Основа - окрема копія лендингу №8. Попередні сайти й репозиторії залишаються окремими.

| Поле | Тип / name | Правило |
|---|---|---|
| Ім’я | text / username | 2–60 символів після trim і NFC; кирилиця/латиниця, пробіл, апостроф, дефіс; без цифр та емоджі |
| Email | email / email | навчальне правило ASCII email, до 254 символів; крапки не повторюються в локальній частині; домен із крапкою |
| Телефон | tel / phone | строго +380 та рівно 9 цифр; введення не переписується автоматично |
| Повідомлення | textarea / message | 10–1000 символів після trim; HTML залишається текстом і не вставляється в DOM |
| Згода | checkbox / agreement | checked обов’язково |

## Взаємодія

Початковий стан нейтральний. Blur позначає поле як відвідане й перевіряє його. Input оновлює вже перевірені поля; валідне нове поле може отримати позитивний стан без показу ранньої помилки. Submit перевіряє всі поля й фокусує перше невалідне.

Під кожним полем є пов’язані helper/error/status. Помилка - червона рамка, текст і aria-invalid=true. Успіх - зелена рамка та зрозумілий текст; доступність не залежить лише від кольору.

Успіх - статичне повідомлення про клієнтську перевірку без реального надсилання. Форма очищається. Native dialog.showModal робить фон неактивним і забезпечує модальну клавіатурну поведінку. Закривання кнопкою, Escape або кліком поза карткою; після закриття фокус повертається на кнопку форми. Повторний submit під час відкритої модалки ігнорується.

## Верстка й безпека

Mobile-first: одна колонка; від md ім’я й email у двох колонках; решта блоків на повну ширину. Контейнер центрований і має max-width; поля й кнопки висотою не менше 48 px. Політика пояснює навчальний характер оброблення.

Форма не використовує fetch, localStorage або innerHTML для введених даних. Без JavaScript кнопка відправлення залишається вимкненою та показується noscript-пояснення. Справжній бекенд вимагав би окремої серверної валідації.
