# Аудит реалізації Codex

Дата: 2026-11-18. Перевірено фактичні index.html, validation.js, validation-rules.mjs, tests/validation.test.mjs і конфігурацію збірки. Це аудит поточним Codex, не окремий сеанс Copilot/Claude. Повторна генерація всієї сторінки не виконувалася.

| Питання аудиту | Висновок / дія |
|---|---|
| Чи строгий телефон? | Так: +380 і 9 цифр, без trim/нормалізації; негативні тести на пробіл, дефіс, дужки, зайву цифру, newline. |
| Чи перевіряє email існування скриньки? | Ні, лише навчальний ASCII-формат; обмеження явно записано в README і звіті. |
| Чи довіряти лише regex? | Ні: окремі довжини/trim, обов’язкова згода, submit всіх полів. Серверна перевірка потрібна при майбутньому API. |
| Чи є передчасні помилки? | Нове невалідне поле під час першого input нейтральне; blur/submit показує помилку, наступний input оновлює її. |
| Чи безпечний вивід? | Повідомлення через textContent; введене користувачем не вставляється через innerHTML. Немає API-запитів із контактами. |
| Чи доступна модалка? | Native dialog, назва й опис aria, close/cancel, відновлення фокусу; позитивний сценарій перевірено в Edge. |
| Чи достатній max-length? | UI має maxlength; чисті функції окремо відхиляють перевищення. Довжина — JS UTF-16, не графеми. |
| Чи готова збірка? | npm ci, build:site та 42 Node-тести пройдено; dist містить .mjs. Статичні перевірки label/id/aria/ресурсів пройдено. |
| Чи є CI/CD? | Два GitHub-статуси success та два Vercel Ready для 9adb404 / 35bd4be підтверджені; друга версія з новою підказкою доступна публічно. |
